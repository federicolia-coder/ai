## Quality bar
- claude.com/product/overview (viewed): shows capability as "the conversation / the result" pairs with real product UI, not feature prose.
- linear.app (inferred, fetch blocked): hero restraint, real product at scale, one quiet secondary action.

## Borrow
- Palette/material: existing Tarry mascot (yellow #eab308 + violet eye) is the only saturated pair; everything else warm neutral.
- Type/hierarchy: one family (Manrope), hierarchy from size and weight only, no gradient text.
- Layout/composition: claude.com -> request/result pairs as the main visual language; every capability shown as a real chat exchange with visible tool steps.
- Motion/interaction: the hero chat plays its own tool steps once, like the product does; sections fade up on entry.
- Asset language: product UI fragments built from the app's real chat components, Phosphor icons, real format/connector marks.

## Avoid
- Hero with no visual, 4 identical icon cards, numbered 01/02/03 steps (the previous version of this site).
- Gradient headline text, purple glow, fake browser chrome, invented testimonials or user counts.

## Direction contract
- Thesis: Tarry checks before it answers, and shows how.
- First viewport: headline on the left, a live Tarry conversation on the right that runs a file read and a calculation.
- System: warm neutrals + brand yellow as spark, ink CTA in light mode, Manrope, Phosphor, IntersectionObserver motion.
- Risk: too many chat mockups can feel repetitive; each one must show a different tool and outcome.
